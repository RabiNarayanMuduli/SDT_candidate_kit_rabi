# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Used naive `punch_in.replace()` anchored to punch-in calendar day rather than attendance day (fails on overnight shifts). Checked `minutes > 10` instead of strict 10-minute grace period (`> 10:00` elapsed). Did not truncate instants to whole seconds. | Punch-in at 00:05 on a 22:00 overnight shift gave negative minutes; punch-in at 09:40:00 on a 09:30 shift returned 10 min late instead of 0. | Anchored `shift_start` to the attendance date in IST; truncated seconds (R1); computed whole floor minutes from `shift_start` only when `diff_sec > 600` (R2). |
| 2 | `compute_work_hours` | Used Python's built-in `round(..., 2)` which performs banker's rounding (round-half-to-even) instead of mathematical round half-up (R4, R8). Did not truncate seconds. | A work duration of 2.555 hours rounded to 2.55 instead of 2.56. | Truncated instants to whole seconds and used `Decimal.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`. |
| 3 | `compute_overtime` | Handled shift end on same calendar date without overnight shift support (`shift_end <= shift_start`). Counted any positive minutes (`max(0, ...)`), missing R3's rule that overtime is counted only when elapsed minutes $\ge 30$. | Punch-out 5 min after shift end yielded 5 min overtime instead of 0; overnight shift punch-out gave negative/invalid overtime. | Advanced `end_date` by +1 day for overnight shifts; returned floor minutes only when `diff_sec >= 1800` (30 min), otherwise 0. |
| 4 | `health` (`GET /health`) | Unconditionally returned `{"status": "ok"}` without checking if MongoDB is alive. Contract specifies readiness probe returning 200 only if MongoDB responds to ping, else 503. | Stopped MongoDB or provided unreachable URI; `/health` still responded 200 instead of 503. | Executed `client.admin.command('ping')` and caught connection failures to raise `HTTPException(503, "Database unavailable")`. |
| 5 | `create_employee` (`POST /employees`) | Relied on check-then-insert (`find_one` then `insert_one`), causing a race condition under concurrency. Did not validate `shift_start != shift_end`. Missing input format validation. Stored naive `datetime.now()` and returned datetime instead of integer epoch ms. | Concurrent requests with the same `emp_code` created duplicates; response contained datetime objects; allowed identical shift start and end times. | Enforced database unique index on `emp_code` and caught `DuplicateKeyError` to return 409; added Pydantic validators; serialized `created_at` as epoch ms integer. |
| 6 | `list_employees` (`GET /employees`) | Pagination off-by-one: `skip = page * page_size` skipped the entire first page (page 1 skipped 20 items). `total` counted whole collection instead of filtered query `q`. Results were not sorted by `emp_code` ascending. | `GET /employees?page=1` returned items starting from index 20; `total` did not reflect department filter; items were unordered. | Changed skip calculation to `(page - 1) * page_size`, added `.sort("emp_code", 1)`, set `total = db.employees.count_documents(q)`, and serialized `created_at` to epoch ms. |
| 7 | `punch_in` (`POST /attendance/punch-in`) | Check-then-insert race condition on `(emp_code, date)`. Crashed with 500 `TypeError` when employee did not exist (`emp["shift_start"]`). Allowed non-presence statuses (`ABSENT`, `LEAVE`). `punched_at` lacked range/epoch-ms validation. Date calculation failed for overnight shifts. Returned non-standard `id` field. | Punching in for non-existent employee returned 500 instead of 404; concurrent punch-ins created duplicates; overnight punch-in at 05:00 took wrong calendar day. | Checked employee existence returning 404; resolved attendance date per R1; added unique compound index on `(emp_code, date)` catching `DuplicateKeyError` (409); validated status/epoch ms; formatted response matching schema. |
| 8 | `list_attendance` (`GET /attendance`) | Scalability flaw: loaded all matching documents into memory (`list(db.attendance_logs.find(q))`) and sorted in Python. Memory slicing for pagination. Missing validation for `date_from <= date_to` (contract requires 422). Secondary sort by `emp_code` missing. Returned `id` from `_id`. | Testing with 100k documents caused memory exhaustion and timeouts; passing `date_from > date_to` returned 200 instead of 422. | Validated `date_from <= date_to` (422); pushed sorting and pagination into MongoDB via `.sort([("date", -1), ("emp_code", 1)]).skip(...).limit(...)` using compound index; converted BSON dates to epoch ms. |
| 9 | `MongoClient` & Startup Lifecycle | `MongoClient` initialized without `tz_aware=True`, yielding naive datetimes. No indexes created at startup, violating unique constraints and causing collection scans (`COLLSCAN`). `load_dotenv()` lacked `override=False`. | PyMongo returned naive datetimes causing comparison issues with aware datetimes; environment variables in container could be overridden by `.env`. | Configured `MongoClient(..., tz_aware=True)`, `load_dotenv(override=False)`, and registered an async `lifespan` handler creating required indexes idempotently. |

Also note anything you looked at and decided was **not** a defect, and why:
- **`IST` defined with fixed offset `timedelta(hours=5, minutes=30)`**: Examined whether `zoneinfo.ZoneInfo("Asia/Kolkata")` was required. Decided `timezone(timedelta(hours=5, minutes=30))` is correct and self-contained: Indian Standard Time has never observed Daylight Saving Time, avoiding external tzdata dependencies.
- **Omission of `history` and `half_day` in older records**: Seeded documents in `DATA_MODEL.md` (Sample 9) show legacy records omit `history` and `half_day`. Verified that default values (`history: []`, `half_day: False`) must be applied gracefully during serialization rather than treating missing fields as data corruption.
